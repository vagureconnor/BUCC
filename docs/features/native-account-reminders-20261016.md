# 原生账号、课程签到与外观验证

## 账号入口

设置的账号配置现包含 Accoding、PatPat、TD 健康云。PatPat 显示自己的已保存账号状态，点击复用作业中心既有的 `HomeworkSource.PATPAT` 登录弹窗；不使用校园统一认证账号，不改变现有 PatPat 接口，不因历史 HTTP 400 自动重发。合成 UI 测试先确认旧设置没有入口，再验证新入口、保存状态与独立回调。

## 课程签到位置

课程签到不进入首页或完整待办列表。首页课程卡直接读取签到状态，仅在该卡日期为今天、签到窗口有效、名称及可用起止时间匹配且候选唯一时显示签到按钮。按钮复用原课程签到回调与进行中状态，不触发课程详情点击。缺少可靠匹配或有歧义时不猜关联，也不退回待办；课程详情与课程签到专页仍保留。

签到窗口、课程卡匹配和普通作业保留由单元/UI 测试覆盖。新增跨日回归先失败再修复：今天有效的签到不得挂到明日同名同时段课程。本次没有执行真实签到写操作。

## 外观与通知证据边界

主题具备跟随系统、浅色、深色三种模式，按主账号保存；测试覆盖默认值、所有模式保存读取、非法值回退和账号隔离。2026-10-16 在 iPhone Simulator 实际检查固定浅色、固定深色，以及跟随系统从浅到深再回浅，界面均生效，最终恢复跟随系统及原系统浅色。Mac 使用相同 Compose 主题与偏好实现，但本次没有完成 Mac 三模式实际切换验收。

通知 planner 定向测试通过，课程开始前十分钟安排，未知开始时间不猜，重复课程事件去重，过期触发不安排。实际 iOS 只读检查确认通知已授权、系统中有待触发请求；不保存请求正文或课程/账号信息。系统容量上限为 64，平台优先近期课程并提示定期打开应用补齐后续提醒。实际到点展示、点击跳转以及 Mac 的通知投递尚未本轮验收，不能以 pending 请求代替已展示。

记住账号已在当前 iOS 会话确认开启且匹配的安全凭据存在；应用重启可恢复首页。过期后的凭据自动登录由 16 项合成测试覆盖。同日另做了受控客户端失效验证：先在树外私密备份，再清除当前模式认证记录、应用 Cookie 及相关系统认证 Cookie；重启后 preload 无挑战，读取匹配安全凭据，未人工输入便恢复同账号首页，新认证记录时间发生变化。服务器主动吊销会话与验证码/MFA 仍未实网验收，验证码/MFA 保持本人输入。临时诊断已移除，正式包不含探针。
