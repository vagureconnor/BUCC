# 纸飞机一键流程契约（2026-10-16）

本文补充本轮实现路径与状态解释。历史接口来源、静态脚本证据和纸飞机身份字段见 [纸飞机查看记录契约（2026-10-15）](paper-plane-contract-20261015.md)。不记录个人身份、课程记录或积分余额。

## 一键流程

一键操作从当前 BUCC 会话读取 SPOC 课程、投掷规则和任务状态；只选择最近一节时间和编号均可确认的已结束课程。必要时补交“收获满满”课堂感受，使用可确认的“案例教学”关键词和官方教师记录，随后按顺序匿名投掷五次。课程、规则、身份、教师、关键词或权限无法确认时停止，不猜测字段或替换内容。写请求遇到失败、超时或不明确回执时不自动重放，并保留同一课程的防重复保护。

查看记录采用已验证的学生映射：请求体 `jllx` 使用学生类型，和 HTTP `RoleCode` 分离。身份映射及用户类型不明确时不写。查看前先读官方 `sfyjl`；已查看条目跳过，明确未查看才向 `/spocnewht/inco/ht/add` 写入。列表按页读取并去重；首屏已查看时继续读取下一页。若投掷后的课堂列表刷新失败，客户端重新读取 feed；不得把刷新失败时的空占位列表当作官方空列表。

流程收尾重新查询官方任务状态。只有成功刷新到有效的官方投掷与查看次数，且两项均达到当日目标，才显示已完成。刷新失败、任务缺失/重复、非法次数、部分投掷或部分查看均显示必要错误；不能用缓存次数、本地累加或投掷数代替查看数。

## 计数含义与页面

`PaperPlaneOneClickSummary.sent` 与 `browsed` 表示本次调用新增的投掷和查看数。`points.list` 中经官方任务接口返回的 `num` 才表示今日累计数。已完成每日查看任务时，本次新增查看可以是 0；UI 应显示官网今日投掷/查看总数，并把本次新增查看数单独标注，不能把 0 说成今日查看总数，也不能仅因 `sent` 达到 5 就报成功。

页面保持积分、金币提示、今日投掷/查看次数、一键操作和简短错误。教师、课程清单、后台步骤和诊断事件不显示在前台。

## 接口与诊断

SPOC 请求使用 BUCC 自有 Token 和 HTTP `RoleCode`，加密业务参数通过 JSON `param` 传递。身份查询为 `POST /spocnewht/grzx/queryByInfo`；任务、用户类型、查看状态、列表和投掷接口均见前述契约。查看状态与标记写入分别走官方查询和新增记录路径。具体请求标识不在本文重复，避免脱离官方契约误用。

纸飞机诊断模块记录 `ONE_CLICK`、`PREPARE_THROW`、`THROW`、`TASKS`、`FEED`、`VIEW` 与 `SPOC_IDENTITY` 操作及其阶段结果。诊断只保存在本地，字段白名单、路径、开关、容量和读取命令见[本地诊断日志说明](../tech/local-diagnostics.md)。

## 验证边界

已有回归覆盖串行五次投掷、部分写入后停止、重复调用保护、查看状态刷新失败及第一页已查看后继续第二页。本轮补充覆盖课堂 feed 刷新失败后的重新读取，以及本次新增查看数为零但官方今日总数已完成的显示语义。

本轮 iOS Simulator 完成一次有界的一键流程验收：起始官方今日投掷/查看任务计数为 `0/0`；流程后 BUCC 内置页面显示官方今日计数为投掷 `5`、查看 `5`，本次新查看为 `5`。官方任务只读刷新与脱敏本地诊断中的 HTTP 事件分别核对；本次新增数没有用作今日累计数。最初的任务读取遇到 SPOC 登录错误；用户完成 BUCC 主登录后，执行只读刷新恢复，再点击一次一键操作。写请求只执行这一次，没有重放。本文不记录账户、积分余额或个人标识。

本次实网验收只证明这一设备、会话和一次流程的结果，不外推其他会话或未来请求；二维码渠道、订单状态和付款与纸飞机验收无关。其他验证结果以主任务最终报告为准。
