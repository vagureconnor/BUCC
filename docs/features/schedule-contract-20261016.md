# 课表互补记录合并契约（2026-10-16）

本补充说明课表来源中同一节课的互补记录如何合并，以及本轮脱敏实证的边界。记录只比较字段关系，不保存课表原值、课程名、个人标识或地点原文。

## 识别与合并

合并在共享课表规范化层执行，供在线课表、已保存/导入课表、首页日程与提醒使用。只有日期和课程身份可靠且候选唯一时才合并：候选必须是同一日期、相同非空课程代码，并由相同课程序号、相同教学对象或相同有效完整节次范围（开始节与结束节都存在且相同）建立身份。候选必须互为唯一匹配；有多个可能对象时保留原记录。

已知字段冲突会阻止合并，包括课程名、班组/课程序号、教学对象、教师周信息、完整节次、开始/结束时间或不兼容地点。一个来源缺少值而另一个来源提供可确认值时，保留已知值；时间未知可以由同一可靠身份记录中的确定时间补齐。地点按楼栋、房间、公寓等信息判断兼容性和具体程度，不以字符串长短决定。

仅标题与日期相同不足以确认同一节课。不同完整节次、不同已知时间或地点冲突时保留独立记录，不猜测地点或时间。课表周的日期与编号不一致时不会把记录并在一起。

## 本轮脱敏实证

比较官方缓存与互补记录时，`courseCode` 和上课日期相同，完整节次均为第 2 至第 5 节；一条记录没有时间，另一条有 `08:50–12:15`。`serial`、`target`、`teacher` 字段在其中一侧缺失。未保存字段原值。完整节次一致为此类记录提供了强身份证据，缺失字段可由互补记录补齐；结果仍须通过唯一匹配和所有已知字段冲突检查。

本轮增加了合成数据 RED 用例，覆盖完整节次在 `serial`、`target`、`teacher` 不完整时仍可作为身份依据，并修复该规则。归一化仍要求配对唯一，并拒绝已知冲突。这里的真实缓存核对只比较字段关系，未保存或披露原始课表内容。

## 进入视图与验证边界

在线周课表在解析后归一化；repository 对在线、缓存及完整学期导入结果也归一化；首页/提醒在跨周聚合前归一化。归一化不改变课表查询的周范围，也不减少独立时段记录。

本文件记录实现规则和本轮已知证据；完整测试结果以主任务验证报告为准。含糊身份、互不唯一候选及已知冲突均应保留为多条记录，等待权威来源提供更强字段证据。

最终 iOS Simulator 安装后，首页已实际显示一张合并课程卡：采用已知开始/结束时间并保留具体教室；未知结束时间标记不再出现。该页面验收与合成测试、缓存字段关系核对分别记录。
